# ТЗ: голосовой секундомер для виса на перекладине

## Контекст и цель

Пользователь тренирует вис на перекладине. Во время виса он **не может смотреть на экран телефона** — телефон лежит на тумбочке, пользователь висит на турнике. Информацию о времени он получает **только через наушник**.

Приложение должно голосом отсчитывать секунды виса, чтобы пользователь понимал, сколько он уже провисел, не глядя на экран.

**Дизайн не важен.** Приоритет — надёжность звука и точность отсчёта. Не трать время на красоту.

---

## Формат поставки

- **Один файл `index.html`**. Весь CSS и JS внутри него.
- Никаких сборщиков, npm, фреймворков, внешних CDN. Открывается двойным кликом и работает.
- Должно работать в мобильном браузере (Safari на iOS, Chrome на Android).
- Кодировка UTF-8, `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.

---

## Основной сценарий работы

1. Пользователь надевает наушники, открывает страницу, нажимает **START**.
2. Голос произносит подготовительный отсчёт: `three` … `two` … `one` … `GO` (по одному слову в секунду).
3. **Ровно в момент слова "GO"** запускается секундомер (t = 0).
4. Далее голос называет секунды на английском:
   - с 1-й по 20-ю секунду — **каждую секунду**: `one`, `two`, `three`, … `twenty`
   - после 20-й секунды — **каждые 5 секунд**: `twenty five`, `thirty`, `thirty five`, `forty` и так далее без верхнего предела
5. Пользователь спрыгивает и нажимает **STOP**.
6. Голос произносит итог: число секунд + слово `seconds` (например: `forty three seconds`). Результат появляется в списке подходов.
7. Кнопка **RESET** сбрасывает таймер в ноль.

## Требования к точности (критично)

Это главная техническая часть задания. Отнесись к ней серьёзно.

### Не накапливать дрейф

**Нельзя** считать время через `setInterval(fn, 1000)` с инкрементом счётчика — за минуту накопится заметная ошибка.

Правильный подход:
- зафиксировать `startTime = performance.now()` в момент старта;
- текущее время всегда вычислять как `performance.now() - startTime`;
- каждое озвучивание планировать **по абсолютной целевой метке**: озвучка N-й секунды планируется на `startTime + N*1000`, а не «через секунду после предыдущей».

Реализация: короткий тик (`setInterval` ~50–100 мс или `requestAnimationFrame`), который сравнивает фактическое `elapsed` с расписанием и произносит все ещё не произнесённые метки, у которых время наступило.

### Компенсация задержки синтеза речи

Между вызовом `speak()` и реальным началом звука проходит 100–200 мс. Чтобы слово «десять» звучало **в момент** десятой секунды, а не после неё, вводи опережение:

```js
const SPEECH_LEAD_MS = 150; // вынести в настройки, диапазон 0–400
```

Озвучка метки N запускается при `elapsed >= N*1000 - SPEECH_LEAD_MS`.

### Не давать речи выстраиваться в очередь

`speechSynthesis` ставит фразы в очередь, и если фраза не успела договориться, следующая ждёт — счёт начинает отставать лавинообразно.

**Обязательно:** перед каждым новым произношением вызывать `speechSynthesis.cancel()`. Лучше обрезать предыдущее слово, чем сдвинуть всё расписание.

### Скорость речи

По умолчанию `utterance.rate = 1.2`. Английские числительные до `twenty` укладываются в секунду с запасом. Сделай слайдер настройки rate от 0.8 до 2.0.

## Работа с Web Speech API

```js
const u = new SpeechSynthesisUtterance(text);
u.lang = 'en-US';
u.rate = settings.rate;
u.pitch = 1;
u.volume = 1;
speechSynthesis.cancel();
speechSynthesis.speak(u);
```

### Разблокировка звука на iOS

Safari на iOS запускает синтез речи **только после жеста пользователя**. Поэтому:
- при первом нажатии на START синхронно, прямо в обработчике клика, произнести пустую или очень короткую фразу (`new SpeechSynthesisUtterance(' ')`), и только потом запускать таймеры;
- ни в коем случае не вызывать первый `speak()` из `setTimeout` — жест уже «протухнет».

### Выбор голоса

Голоса подгружаются асинхронно. Подписаться на `speechSynthesis.onvoiceschanged`, выбрать первый доступный с `lang.startsWith('en')`. Если английского голоса нет — не падать, использовать голос по умолчанию.

### Известный баг Chrome

В десктопном Chrome синтез сам обрывается примерно через 15 секунд непрерывной работы. Так как здесь произносятся короткие отдельные слова, проблема маловероятна, но если проявится — применить приём с периодическим `pause()`/`resume()`.

## Экран не должен гаснуть

Если экран телефона погаснет или страница уйдёт в фон, отсчёт может остановиться (особенно на iOS).

Обязательно использовать **Screen Wake Lock API**:

```js
let wakeLock = null;
async function acquireWakeLock() {
  try { wakeLock = await navigator.wakeLock.request('screen'); } catch (e) { /* не критично */ }
}
```

- запрашивать при старте, освобождать при стопе;
- **обязательно** переподнимать в обработчике `document.visibilitychange`, когда страница снова становится видимой — иначе лок теряется навсегда;
- если API не поддерживается — не падать, а показать на экране предупреждение: «Wake Lock недоступен, поставьте в настройках телефона автоблокировку экрана на "Никогда"».

Wake Lock требует HTTPS (secure context) — на GitHub Pages работает, при открытии файла через `file://` не работает.

## Интерфейс

Минимальный, тёмный фон, крупный белый текст.

- **Огромные цифры таймера** по центру (`font-size: clamp(4rem, 25vw, 12rem)`, моноширинный шрифт, `font-variant-numeric: tabular-nums`, чтобы не прыгала ширина). Формат `MM:SS` или просто число секунд.
- **Три кнопки во всю ширину, высотой не меньше 80px** — попасть должно получаться одной рукой, не глядя. START (зелёная) / STOP (красная) / RESET (серая).
  - START и STOP можно объединить в одну кнопку-переключатель, если так проще.
- Во время подготовительного отсчёта на экране крупно показывать `3`, `2`, `1`, `GO`.
- Блок **настроек**, свёрнутый по умолчанию (`<details>`):
  - длина подготовки: 3 / 5 / 10 секунд (по умолчанию 3);
  - скорость речи: слайдер 0.8–2.0 (по умолчанию 1.2);
  - опережение речи `SPEECH_LEAD_MS`: слайдер 0–400 мс (по умолчанию 150);
  - режим озвучки: «каждую секунду до 20, дальше каждые 5» (по умолчанию) / «каждую секунду всегда» / «каждые 5 секунд»;
  - кнопка **TEST VOICE** — произносит `one two three`, чтобы проверить звук в наушниках до начала подхода.
- **История подходов**: список последних 10 результатов текущей сессии, с лучшим результатом отдельной строкой. Хранить в `localStorage` (ключ `hangTimer.history`), настройки тоже в `localStorage`.
- Кнопка «очистить историю».

## Крайние случаи

- Повторное нажатие START во время работы таймера ничего не ломает (либо игнорируется, либо работает как STOP).
- Нажатие STOP во время подготовительного отсчёта — отменяет отсчёт, ничего не записывает в историю.
- STOP на нулевой секунде — не добавлять пустой результат в историю.
- При уходе страницы в фон и возврате — таймер продолжает показывать корректное время (оно считается от `performance.now()`, а не от количества тиков). Пропущенные за время фона озвучки **не проговаривать пачкой** — озвучить только актуальную последнюю метку или пропустить.
- Двойной тап по кнопке не должен зумить страницу: `touch-action: manipulation`, `user-select: none`.

## Критерии приёмки

Проверить самостоятельно перед сдачей:

1. Нажатие START → слышно `three, two, one, GO`, и сразу после `GO` таймер на экране пошёл с нуля.
2. Числа на экране и произносимые числа совпадают. Проверить на 30-секундном прогоне вместе с обычным секундомером — расхождение к 60-й секунде не больше 0.5 с.
3. После `twenty` следующее произнесённое число — `twenty five`, затем `thirty`.
4. STOP → произносится итог, результат попал в историю.
5. Страница работает при открытии на телефоне, кнопки нажимаются без прицеливания.
6. Консоль браузера чистая, без ошибок.
